# HydroTune: LLM-Agent-Guided Automatic Calibration and Deep Learning Error Correction for Modular Hydrological Models

## Abstract
- **Background & Problem** / 背景与问题：Conceptual hydrological models require labor-intensive manual calibration, and the selection of appropriate models and parameters across diverse watershed conditions remains challenging. / 概念性水文模型需要大量人工率定，且在不同流域条件下选择合适模型与参数仍具挑战。
- **Objective** / 目标：We present HydroTune, an LLM-agent-guided platform that automates the end-to-end workflow from raw data upload to intelligent calibration reports. / 我们提出HydroTune，一个由LLM代理引导的从原始数据上传到智能率定报告的全自动化平台。
- **Methods** / 方法：The system integrates (1) a flood semantic encoder that translates numerical hydrograph data into structured multi-modal representations for LLM consumption, (2) five optimization algorithms (Two-Stage, PSO, SCE-UA, DE, GA) for multi-model (Tank, HBV, Xinanjiang) calibration, and (3) XGBoost-based error correction as a hybrid physics-ML approach. / 系统集成了(1)将数值水文过程线数据转化为结构化多模态表示供LLM消费的洪水语义编码器，(2)五种优化算法用于多模型率定，(3)基于XGBoost的误差校正作为物理-ML混合方法。
- **Key Results** / 关键结果：Validated on two contrasting case studies—a small-sample scenario (3 events) and a large-sample scenario (57 events)—demonstrating the platform's robustness across data-scarce and data-rich conditions. / 在两个对比案例（3场小样本和57场大样本）上验证，展示了平台在数据稀缺和数据丰富条件下的鲁棒性。
- **Significance** / 意义：HydroTune bridges the gap between AI and operational hydrology by enabling non-expert users to perform professional-grade model calibration with LLM-generated diagnostic reports. / HydroTune通过使非专业用户能够进行专业级模型率定并生成LLM诊断报告，弥合了AI与业务水文学之间的鸿沟。

## 1 Introduction / 引言
- **Hydrological model calibration challenge** / 水文模型率定挑战：Conceptual models (Tank, HBV, Xinanjiang) contain 3–21 parameters requiring calibration. Manual calibration is expert-intensive, time-consuming, and often inconsistent across operators. / 概念性模型含3-21个需率定参数，人工率定依赖专家经验，耗时且不同操作者间结果不一致。
- **Existing auto-calibration tools** / 已有自动率定工具：Tools like PEST, OSTRICH, and SWAT-CUP provide optimization frameworks but lack intelligent data analysis, multi-model comparison, and actionable diagnostic reporting. / PEST、OSTRICH、SWAT-CUP等工具提供优化框架，但缺乏智能数据分析、多模型比较和可操作的诊断报告。
- **LLM in environmental modeling** / 大语言模型在环境建模中的应用：Recent advances in LLMs (GPT-4, Minimax) open new possibilities for intelligent data interpretation, but their application in hydrology remains nascent—mainly limited to literature review and code generation. / LLM在环境建模中的进展开辟了智能数据解读的新可能，但在水文学中的应用仍处于初期，主要局限于文献综述和代码生成。
- **LLM limitations in interpreting raw hydrograph data** / LLM对原始水文过程线数据的理解局限：Despite their impressive reasoning capabilities, LLMs are inherently token-based sequence models that operate on discrete text inputs with constrained context windows (typically 8K–128K tokens). Raw flood hydrograph data presents three fundamental challenges for direct LLM ingestion: (i) *scale mismatch*—a single flood event may span hundreds to thousands of time steps, exceeding practical token budgets while losing statistical coherence when naively truncated; (ii) *numerical reasoning deficiency*—LLMs exhibit well-documented degradation in numerical computation and quantitative trend analysis from raw tabular data, often hallucinating spurious statistical relationships; (iii) *semantic abstraction gap*—hydrologically meaningful concepts such as "rapid rising limb," "sharp peak," or "prolonged recession" are not directly encoded in numerical flow/precipitation vectors, requiring domain-specific feature engineering to render them legible to language models. These limitations motivate the need for a structured intermediate representation—a *semantic encoding*—that distills raw time-series data into compact, linguistically accessible, and hydrologically informative feature vectors before presenting them to the LLM agent. / 尽管LLM具有令人印象深刻的推理能力，但作为基于token的序列模型，其输入窗口受限（通常8K–128K token）。原始洪水过程线数据对LLM直接消费构成三个根本挑战：(i)尺度不匹配—单场洪水可达数百至数千时间步，超出实用token预算，且简单截断会丧失统计连贯性；(ii)数值推理不足—LLM在原始表格数据的数值计算和定量趋势分析中存在显著退化，常产生虚假统计关系的幻觉；(iii)语义抽象鸿沟—水文学上有意义的概念如"陡涨""尖峰"或"长退水"并非直接编码在数值流量/降水向量中，需要领域特定的特征工程才能使其对语言模型可读。这些局限驱动了对结构化中间表示即语义编码的需求。
- **The case for hybrid physics-ML modeling in operational hydrology** / 物理-ML混合建模在业务水文学中的必要性：Conceptual hydrological models, despite their parsimonious parameterization and physical interpretability, exhibit inherent structural limitations: (i) *simplified process representation*—lumped or semi-distributed parameterizations (e.g., single-valued soil moisture capacity, linear reservoir routing) cannot fully resolve the spatiotemporal heterogeneity of real catchments, leading to systematic biases in peak timing, magnitude, and recession behavior; (ii) *stationarity assumption*—calibrated parameter sets implicitly assume stationary rainfall–runoff relationships, whereas real watersheds undergo non-stationary changes (land-use alteration, climate variability, reservoir regulation) that degrade model performance over time; (iii) *residual information*—even well-calibrated models leave structured residuals in the simulated-minus-observed error time series that carry exploitable information about unmodeled processes. / 概念性水文模型虽参数简约且物理可解释性强，但存在固有结构限制：(i)简化的过程表示—集总式或半分布式参数化无法完全解析真实流域的时空异质性；(ii)平稳性假设—率定参数隐式假定平稳的降雨-径流关系，而真实流域经历非平稳变化；(iii)残差信息—即使良好率定的模型，其误差时间序列中仍保留着可被利用的未建模过程信息。
- **Complementary strengths of ML-based error correction** / 机器学习误差校正的互补优势：Data-driven error correction models (e.g., XGBoost, LSTM) offer complementary capabilities: they can learn complex, nonlinear mapping from predictor features (error lags, precipitation lags) to model residuals without specifying physical equations; they adapt to non-stationary patterns when retrained on recent observations; and they operate as post-processors that preserve the physical model's core hydrological constraints (water balance, process causality) rather than replacing them with a black-box. A growing body of literature demonstrates that hybrid approaches—conceptual model + ML residual learner—consistently outperform either component alone, particularly for flood peak prediction where structural errors are most consequential. / 数据驱动的误差校正模型提供互补能力：它们可以在不指定物理方程的情况下从预测特征学习到模型残差的复杂非线性映射；通过近期观测重训练适应非平稳模式；作为后处理器保留物理模型核心水文约束（水量平衡、过程因果）而非用黑箱替代。越来越多的文献证明混合方法持续优于单一组分。
- **Gap in operational tooling** / 业务工具的缺口：Despite the demonstrated efficacy of hybrid physics-ML approaches in research settings (custom Python/R scripts, offline case studies), no existing operational calibration platform integrates ML-based error correction as a native, configurable module within an automated calibration workflow. Current tools (PEST, SWAT-CUP, OSTRICH) neither couple model residuals with ML post-processors nor provide the event-based train/validation split logic required to prevent data leakage in operational forecasting contexts. Closing this gap is critical for translating hybrid modeling research into actionable decision-support tools for flood forecasting agencies and water resource managers. / 尽管混合物理-ML方法在研究环境中已证明有效，但尚无现有业务率定平台将ML误差校正作为原生可配置模块集成到自动化率定工作流中。当前工具既不将模型残差与ML后处理器耦合，也不提供防止操作预报数据泄漏的按场次训练/验证划分逻辑。弥合这一缺口对于将混合建模研究转化为洪水预报机构可操作的决策支持工具至关重要。
- **Research gap & contributions** / 研究缺口与贡献：
  - (1) We propose a novel *flood semantic encoding* paradigm that transforms raw hydrograph time series into structured, multi-attribute representations (magnitude, peak morphology, rise/recession dynamics, rainfall forcing), thereby bridging the modality gap between numerical hydrological data and LLM-based reasoning—to our knowledge, the first such encoding scheme designed explicitly for LLM-agent-guided hydrological analysis. / 提出一种新颖的洪水语义编码范式，将原始水文过程线时序数据转化为结构化多属性表示（量级、峰型、涨落动力学、降水驱动），从而弥合数值水文数据与LLM推理之间的模态鸿沟—据我们所知，这是首个专为LLM代理引导的水文分析设计的语义编码方案。
  - (2) We develop a *unified multi-model, multi-algorithm calibration framework* that integrates three conceptual hydrological models of varying complexity (Tank: 3 parameters; HBV: 10 parameters; Xinanjiang: 21 parameters) with five global optimization algorithms (Two-Stage, PSO, SCE-UA, DE, GA) under a single abstract interface, enabling systematic model intercomparison and algorithm benchmarking within an operational context. / 构建统一的多模型、多算法率定框架，在单一抽象接口下集成三种不同复杂度的概念性水文模型（Tank: 3参数; HBV: 10参数; 新安江: 21参数）与五种全局优化算法（两阶段法、PSO、SCE-UA、DE、GA），使业务场景下的系统化模型对比与算法基准测试成为可能。
  - (3) We introduce a *hybrid physics-ML error correction architecture* wherein an XGBoost regressor, trained on error-lag (e_{t-1}, ..., e_{t-5}) and precipitation-lag (p_{t-1}, ..., p_{t-3}) features, learns the systematic residuals of conceptual model simulations; the approach is validated under an event-based train/test split strategy that prevents temporal leakage across flood events, and is benchmarked against both recursive and oracle correction modes. / 引入一种物理-ML混合误差校正架构，其中以误差滞后（e_{t-1}, ..., e_{t-5}）和降水滞后（p_{t-1}, ..., p_{t-3}）为特征的XGBoost回归器学习概念模型模拟的系统残差；该方法在按洪水场次划分的训练/测试策略下验证，杜绝了跨场次的时间泄漏，并以递归模式和oracle模式进行了双模基准测试。
  - (4) We deliver a *fully operational, open-source software platform* (HydroTune) with a Streamlit-based graphical interface, bilingual (Chinese/English) support, and LLM-generated intelligent diagnostic reports that span data pre-analysis, calibration evaluation, and model selection recommendations—demonstrating the feasibility of AI-augmented decision support for non-expert hydrological practitioners. / 交付一个全运营的开源软件平台（HydroTune），具备基于Streamlit的图形界面、中英双语支持以及LLM生成的智能诊断报告（涵盖数据预分析、率定评估和模型选择建议）—证明了面向非专业水文从业者的AI增强决策支持的可行性。

## 2 Methodology / 方法

### 2.1 LLM-based agentic workflow / 基于LLM的智能体工作流
- **HydroAgent architecture** / HydroAgent架构：A lightweight orchestrator class (`HydroAgent`) that chains: data ingestion → model registration → multi-model calibration → performance ranking → report triggers. / 一个轻量级编排器类，串联：数据接入→模型注册→多模型率定→性能排序→报告触发。
- **Agent decision points** / 智能体决策节点：The LLM is invoked at three critical junctures: (a) data quality assessment and time-scale inference, (b) flood event detection and semantic characterization, (c) diagnostic report generation with calibration strategy recommendations. / LLM在三个关键节点被调用：(a)数据质量评估与时间尺度推断，(b)洪水事件检测与语义表征，(c)诊断报告生成与率定策略建议。
- **Language-adaptive design** / 语言自适应设计：A global `get_language()`/`set_language()` toggle switches all prompts, system instructions, and report templates between Chinese and English, enabling international applicability. / 全局语言切换机制在中文和英文之间切换所有提示词、系统指令和报告模板。
- **Tool-use paradigm** / 工具使用范式：The LLM acts as an intelligent analyst rather than a code executor; it receives structured semantic codes and data quality metrics, then produces structured Markdown reports following a 7-section template. / LLM作为智能分析师而非代码执行器，接收结构化语义编码和数据质量指标，按7节模板生成Markdown报告。

### 2.2 Semantic encoding of flood events for LLM agents / 洪水事件语义编码
- **Motivation** / 动机：Raw hydrograph time-series data (hundreds to thousands of time steps) cannot be directly consumed by LLMs due to token limits and numerical reasoning limitations. A structured intermediate representation is required. / 原始水文过程线时序数据（数百至数千时间步）因token限制和数值推理局限无法直接被LLM消费，需要结构化中间表示。
- **FloodSemanticCode dataclass** / FloodSemanticCode数据类：A 15-field structured dataclass capturing: `event_id, magnitude (extreme/large/medium/small), peak_flow, flood_volume, duration, rise_type (rapid/moderate/slow), recession_type, peak_shape (sharp/rounded/multi-peak), rainfall_driven (high/medium/low), representative_score, selection_reason, start_date, end_date, baseflow, peak_ratio, total_precip`. / 15字段结构化数据类，涵盖洪水量级、峰值流量、洪量、历时、涨水类型、退水类型、峰型、降水驱动强度、代表性评分等信息。
- **Classification heuristics** / 分类启发式规则：Each semantic attribute is derived from the flow time series Q(t) (t=1,...,T) and precipitation time series P(t) via well-defined hydrological heuristics. The baseflow Q_base is estimated using a rolling minimum filter over a 5-step window: Q_base = mean(min_{rolling}(Q, w=5)). All classifications below reference the flood event window from start index t_s to end index t_e. The full derivation is formalized in Table 1. / 每个语义属性均通过明确的水文启发式规则从流量时序Q(t)和降水时序P(t)中导出，基流Q_base采用5步滑动窗口最小值估计。
  - Magnitude / 量级：
    - Given the sample mean Q̄_peak and standard deviation σ_peak of historical peak flows,
    - \| extreme: Q_peak > Q̄_peak + 2·σ_peak
    - \| large:   Q_peak > Q̄_peak + σ_peak
    - \| medium:  Q_peak > Q̄_peak
    - \| small:   otherwise
  - Rise type / 涨水类型：
    - Let t_p denote the time index of peak flow, and define the mean rising gradient:
    - \\[ r_{rise} = \frac{Q(t_p) - Q(t_s)}{t_p - t_s} \\]
    - \| rapid:   r_rise > 5.0
    - \| moderate: r_rise > 1.0
    - \| slow:    otherwise
  - Recession type / 退水类型：
    - Define the mean recession gradient:
    - \\[ r_{rec} = \frac{Q(t_p) - Q(t_e)}{t_e - t_p} \\]
    - \| rapid:   r_rec > 3.0
    - \| moderate: r_rec > 0.5
    - \| slow:    otherwise
  - Peak shape / 峰型：
    - Let L = {i : Q(i) > Q(i−1) ∧ Q(i) > Q(i+1)} be the set of local maxima indices.
    - \| multi-peak: |L| > 1
    - \| sharp: left slope ΔL = Q(t_p) − Q(t_p−1) and right slope ΔR = Q(t_p) − Q(t_p+1) satisfy ΔL > 3·ΔR or ΔR > 3·ΔL
    - \| rounded: otherwise
  - Rainfall-driven intensity / 降水驱动强度：
    - Compute the runoff coefficient φ from total precipitation P_total = Σ_{t=t_s}^{t_e} P(t):
    - \\[ \phi = \frac{V_{flood}}{P_{total} \times 0.01} \\]
    - where V_flood is the flood volume in 10⁴ m³.
    - \| high:   φ > 0.3
    - \| medium: φ > 0.1
    - \| low:    otherwise
  - Flood volume / 洪量计算：
    - For daily timestep:
    - \\[ V_{flood} = \frac{\sum_{t=t_s}^{t_e} (Q(t) - Q_{base}) \times 86400}{10000} \\]
    - (units: 10⁴ m³)
  - Peak ratio / 峰基比：
    - \\[ r_{peak} = \frac{Q(t_p)}{Q_{base}} \\]
  - The classification thresholds (gradient values 5.0, 1.0, 3.0, 0.5; runoff coefficient 0.3, 0.1) are default heuristics calibrated to the typical hydroclimatic regime of the study watersheds and can be adjusted for different regions. / 分类阈值为适用于研究流域典型水文气候体制的默认启发式值，可根据不同区域调整。
- **Representative score calculation** / 代表性评分计算：A composite score combining peak-flow similarity, flood-volume similarity, and magnitude-based weighting:
  - \\[ S_{peak} = 1 - \frac{|Q_{peak} - \bar{Q}_{peak}|}{\bar{Q}_{peak}} \\]
  - \\[ S_{volume} = 1 - \frac{|V_{flood} - \bar{V}_{flood}|}{\bar{V}_{flood}} \\]
  - \\[ S_{magnitude} = \begin{cases} 100 & \text{extreme} \\ 85 & \text{large} \\ 70 & \text{medium} \\ 50 & \text{small} \end{cases} \\]
  - \\[ S_{rep} = \left(0.3 \cdot S_{peak} + 0.2 \cdot S_{volume} + 0.5 \cdot \frac{S_{magnitude}}{100}\right) \times 100 \\]
- **P-III frequency analysis integration** / P-III频率分析集成：Pearson Type III theoretical frequency curves are fitted to observed peak-flow and flood-volume series, plotted on probability paper (Hazen coordinate), and annotated with statistical parameters (X̄, Cv, Cs). / P-III型理论频率曲线拟合到观测洪峰和洪量序列上，绘制在概率纸上并标注统计参数。
- **LLM prompt engineering** / LLM提示工程：The `to_json_for_llm()` method serializes all semantic codes into structured JSON, embedded in a detailed prompt that demands 7-section structured output: flood characteristics, anomaly detection, spatiotemporal analysis, representativeness assessment, quality evaluation, calibration strategy, and anomaly handling. / `to_json_for_llm()`将语义编码序列化为结构化JSON，嵌入详细提示词中要求7节结构化输出。

### 2.3 Hydrology models and calibration algorithms / 水文模型与率定算法
- **Model portfolio** / 模型组合：
  - *Tank Model* (3 parameters: k1, k2, c): A multi-layer linear-reservoir cascade. Fast runoff coefficient (k1: 0.01–0.3), slow baseflow coefficient (k2: 0.001–0.05), runoff generation coefficient (c: 0.01–0.3). / 水箱模型（3参数），多层线性水库串联。
  - *HBV Model* (10 parameters: fc, beta, k0, k1, lp, perc, uzl, k2, etc.): The Nordic conceptual model with soil moisture accounting, fast/slow response functions, and evapotranspiration limitation. / HBV模型（10参数），北欧概念性模型，包含土壤水分计算、快慢响应函数和蒸散发限制。
  - *Xinanjiang Model V2* (21 parameters: B, C, WM, WUM, WLM, IM, SM, EX, K, KI, KG, CG, CI, CS, L, X, K_routing, X_routing, etc.): Three-source runoff generation with Muskingum routing, widely applied in humid/semi-humid regions of China. / 新安江模型V2（21参数），三水源产流加马斯京根汇流，广泛用于中国湿润半湿润地区。
- **Optimization algorithms** / 优化算法：
  - *Two-Stage* (default/recommended): Global exploration (Simulated Annealing, dual_annealing) + local refinement (L-BFGS-B), with progress callback for real-time UI updates. / 两阶段算法（推荐）：全局探索(模拟退火)+局部精化(L-BFGS-B)，含进度回调。
  - *PSO*: Particle Swarm Optimization with configurable swarm size, inertia weight, and cognitive/social coefficients. / 粒子群优化，可配置种群规模、惯性权重和认知/社会系数。
  - *SCE-UA*: Shuffled Complex Evolution, a global optimization strategy for complex nonlinear problems. / 洗牌复形进化，适用于复杂非线性问题。
  - *DE*: Differential Evolution with configurable mutation factor, crossover probability, and population size. / 差分进化，可配置变异因子、交叉概率和种群规模。
  - *GA*: Genetic Algorithm with tournament selection, crossover, and Gaussian mutation. / 遗传算法，含锦标赛选择、交叉和高斯变异。
- **Multi-event calibration** / 多场次率定：The `calibrate_model_fast()` function supports event-wise calibration by averaging NSE across multiple flood events, with warm-up period exclusion and upstream routing overlay. / `calibrate_model_fast()`通过平均多场次NSE支持逐场率定，含预热期剔除和上游汇流叠加。
- **Evaluation metrics** / 评价指标：NSE (Nash-Sutcliffe Efficiency), KGE (Kling-Gupta Efficiency), RMSE, MAE, and PBIAS computed with NaN-masked arrays. / 五种评价指标：NSE、KGE、RMSE、MAE、PBIAS。
- **Muskingum routing** / 马斯京根汇流：Optional upstream-to-downstream flood routing with either auto-calibrated or manually specified K and X parameters. / 可选的上下游洪水演算，支持自动率定或手动指定的K和X参数。

### 2.4 Hybrid physics-ML modeling approaches / 物理-ML混合建模方法
- **Rationale** / 设计依据：Conceptual models capture dominant physical processes but exhibit systematic errors (e.g., timing bias, peak underestimation) due to structural simplifications. ML-based error correction can learn residual patterns without replacing the physical model. / 概念性模型捕捉主导物理过程但因结构简化而存在系统误差，ML误差校正可学习残差模式而不替代物理模型。
- **XGBoost error correction** / XGBoost误差校正：
  - Feature engineering: 8 input features = 5 error lags [e(t-1), ..., e(t-5)] + 3 precipitation lags [p(t-1), p(t-2), p(t-3)]. / 特征工程：8个输入特征=5个误差滞后+3个降水滞后。
  - Correction formula: `corrected(t) = simulated(t) + predicted_error(t)`, where `predicted_error(t) = XGB([e(t-1:5), p(t-1:3)])`. / 校正公式。
  - Two prediction modes: (A) recursive correction using XGB-predicted error lags, (B) oracle correction using true error lags (upper-bound benchmark). / 两种预测模式：(A)递归校正(用XGB预测的误差滞后)，(B)oracle校正(用真实误差滞后作上限基准)。
- **Event-based train/test split** / 按场次划分训练/测试集：Events are randomly partitioned into calibration (75%) and validation (25%) sets by event index to prevent temporal data leakage across flood events. Fixed random seed (2025) ensures reproducibility. / 按场次随机划分率定(75%)和验证(25%)集，防止跨场次的时间数据泄漏。
- **BMA ensemble** / BMA集合预报：Bayesian Model Averaging assigns weights proportional to `exp(NSE / temperature)` for multi-model ensemble predictions, improving robustness over single-model outputs. / 贝叶斯模型平均按`exp(NSE/temperature)`分配权重，提高多模型集合预测的鲁棒性。

## 3 Software design / 软件设计

### 3.1 Data upload and configuration of essential parameters / 数据上传与参数配置
- **Dual-mode data ingestion** / 双模式数据接入：Two upload modes: (a) single-file mode for a continuous time series with automatic flood event detection, and (b) multi-file mode where each uploaded file corresponds to one flood event. / 两种上传模式：(a)单文件模式，含连续时序自动洪水检测；(b)多文件模式，每个上传文件对应一场洪水事件。
- **Time-step auto-inference** / 时间尺度自动推断：The system automatically infers the time-step (hourly or daily) by computing the median interval between consecutive timestamps; users can override this inference manually if domain knowledge indicates otherwise. / 系统通过计算连续时间戳的中位间隔自动推断时间尺度（小时或日）；用户可根据领域知识手动覆盖。
- **Human-in-the-loop configuration** / 人在回路中的配置：Users configure essential parameters—catchment area, warm-up period, target hydrological model, optimization algorithm, and XGBoost hyperparameters—via the sidebar before launching the analysis. This human-in-the-loop design is intentional: it anchors the LLM agent's decisions with domain-specific constraints, preventing misinterpretation or hallucination that could arise from fully autonomous, unguided data interpretation by the LLM. / 用户在启动分析前通过侧边栏配置关键参数——流域面积、预热期、目标水文模型、优化算法和XGBoost超参数。这种人在回路中的设计有意为之：它用领域特定约束锚定LLM代理的决策，防止LLM在完全自主、无引导的数据解读中产生误解或幻觉。
- **[Figure suggestion / 建议配图]**：Screenshot of the Streamlit interface illustrating the data upload pane and sidebar configuration panel. / Streamlit界面上传窗格和侧边栏配置面板截图。

### 3.2 Automated data preprocessing and flood event analysis / 自动数据预处理与洪水事件分析
- **LLM-driven data cleaning** / LLM驱动的数据清洗：The system automatically generates a data fingerprint (column types, missing ratios, value ranges) and prompts the LLM to produce cleaning code, which is executed in an isolated sandbox environment with a deterministic fallback path for reliability. / 系统自动生成数据指纹（列类型、缺失率、取值范围）并驱动LLM生成清洗代码，在隔离沙盒中执行，含确定性回退路径以确保可靠性。
- **Automatic flood event detection** / 自动洪水场次检测：Baseflow is estimated via a rolling-window minimum filter; flood events are then identified through anomaly extraction (flow minus baseflow) with threshold-based boundary detection and peak-flow validation. / 基于滑动窗口基流分离与流量异常提取的洪水事件自动检测。
- **Data quality assessment** / 数据质量评估：A 4-axis radar chart (completeness, continuity, correlation, quality level) and P-III frequency analysis provide a structured visual summary of data quality, embedded as context for downstream LLM analysis. / 四轴雷达图与P-III频率分析提供数据质量的结构化可视化摘要，作为下游LLM分析的上下文。
- **[Figure suggestion / 建议配图]**：Multi-panel pre-analysis figure: (a) radar chart, (b) P-III curve, (c) precipitation-runoff scatter, (d) hydrograph with flood event annotations. / 多面板预分析图：(a)雷达图，(b)P-III曲线，(c)降水-径流散点图，(d)含洪水事件标注的过程线。

### 3.3 Automated parameter calibration and deep learning coupling / 自动参数率定与深度学习耦合
- **Unified calibration dispatcher** / 统一率定分派器：A single abstract interface dispatches calibration tasks to any of the five optimization algorithms; parameter bounds are automatically derived from each model's metadata, and the optimizer is selectable at runtime. / 单一抽象接口将率定任务分派到五种优化算法之一，参数边界从模型元数据自动获取。
- **Model-engine separation** / 模型-引擎分离：Pure computational model engines are cleanly separated from calibration logic and user-interface code via adapter wrappers, ensuring that new models can be integrated without modifying the optimization or visualization layers. / 纯计算模型引擎通过适配器与率定逻辑和界面代码解耦，新模型可在不修改优化或可视化层的情况下集成。
- **XGBoost error correction pipeline** / XGBoost误差校正管道：After physical calibration, the system automatically trains an XGBoost error corrector on the calibration event set, evaluates it on the held-out validation events, and reports pre-/post-correction metrics (NSE, RMSE, PBIAS). / 物理模型率定后，系统自动在率定事件集上训练XGBoost误差校正器，在验证集上评估，并报告校正前后指标变化。

### 3.4 Visualization and intelligent report generation / 可视化与智能报告生成
- **Hydrograph comparison** / 过程线对比：Multi-panel plots juxtapose observed, simulated, and post-correction hydrographs for both calibration and validation events, enabling rapid visual assessment of model performance. / 多面板过程线并排对比观测、模拟与校正后流量，支持模型性能的快速视觉评估。
- **Interactive model comparison table** / 模型对比表：A ranked summary table displays NSE, RMSE, MAE, and PBIAS per model with per-event breakdown statistics, facilitating systematic model intercomparison. / 按NSE排序的汇总表展示各模型指标及逐场次分解统计。
- **LLM-generated diagnostic reports** / LLM诊断报告：The system produces four types of structured reports—data pre-analysis, calibration evaluation, comprehensive summary, and overfitting diagnosis—with content generated by the LLM informed by both numerical metrics and embedded visualizations. / 系统生成四种结构化报告，LLM结合数值指标和嵌入式可视化内容生成诊断文本。
- **Visual-aware prompting** / 视觉感知提示：Key diagnostic figures are serialized as Base64-encoded images and injected into LLM prompts, allowing the language model to reason about visual patterns in hydrographs and statistical plots alongside numerical summaries. / 诊断图表以Base64编码注入LLM提示词，使模型能同时基于数值摘要和视觉模式进行推理。
- **Graceful degradation** / 优雅降级：When the external LLM service is unreachable, the platform automatically falls back to a template-based report generated directly from computed metrics, ensuring operational reliability. / LLM服务不可用时的自动模板化回退报告，确保运行可靠性。

### 4.1 Case 1: Small-sample calibration — 多场洪水 A5 (3 events) / 小样本率定
- **Scenario description** / 情景描述：Three flood events from watershed A5 (`20180619`, `20230607`, `20230727`) representing a data-scarce scenario typical of ungauged or poorly gauged basins. / A5流域三场洪水，代表缺资料或监测不足流域的典型数据稀缺情景。
- **Calibration strategy** / 率定策略：Given the limited sample size, a leave-one-event-out cross-validation scheme is adopted: 2 events are used for calibration and the remaining 1 event is held out for validation, with this procedure rotated across all three events. XGBoost error correction is evaluated in oracle mode, as the small sample precludes reliable training of a recursive corrector. / 鉴于样本量有限，采用留一事件交叉验证：2场用于率定、1场留作验证，轮换所有三场，XGBoost误差校正以oracle模式评估因样本量不足训练递归校正器。

## 5 Conclusion and Future work / 结论与未来工作
- **Summary of contributions** / 贡献总结：
  - A fully operational, LLM-agent-guided platform that automates the complete hydrological model calibration lifecycle / 一个全运营的LLM代理引导平台，自动化完整的水文模型率定生命周期
  - Flood semantic encoding as a novel bridge between numerical hydrograph data and LLM reasoning / 洪水语义编码作为数值水文过程线数据与LLM推理之间的新型桥梁
  - Empirical demonstration that XGBoost error correction with error-lag + precipitation-lag features consistently improves NSE, especially for validation events / 实证证明基于误差滞后+降水滞后特征的XGBoost误差校正持续提高NSE
- **Current limitations** / 当前局限：
  - The model library is currently restricted to three lumped conceptual models (Tank, HBV, Xinanjiang), lacking support for semi-distributed or fully distributed hydrological models that are widely adopted in operational agencies. / 模型库当前限于三种集总式概念模型，缺乏对业务机构广泛采用的半分布式或全分布式水文模型的支持。
  - The deep learning coupling is limited to a single XGBoost-based error corrector; more advanced paradigms such as differentiable programming, physics-informed neural networks, or sequence-to-sequence residual learning remain unexplored. / 深度学习耦合仅限于单一XGBoost误差校正器，可微分编程、物理信息神经网络等更先进范式尚未探索。
  - Reliance on a cloud-based commercial LLM (Minimax abab6.5-chat) introduces latency, recurring API costs, and data privacy concerns, particularly problematic for hydrological agencies handling sensitive watershed data. / 依赖云端商业LLM带来延迟、持续API成本及数据隐私问题，对处理敏感流域数据的水文机构尤为不利。
  - The platform operates as a single-site offline calibration tool without integration of real-time sensor data streams, precluding continuous model updating in operational digital twin frameworks. / 平台作为单站点离线率定工具运行，缺乏实时传感器数据流的集成，无法在业务数字孪生框架中持续更新模型。
  - Uncertainty quantification is limited to BMA ensemble spread; full Bayesian inference for posterior parameter distributions and predictive uncertainty is absent. / 不确定性量化限于BMA集合离散度，缺少参数后验分布和预测不确定性的完整贝叶斯推断。
- **Future work** / 未来工作：
  - *Model library expansion*: Extend the model portfolio beyond lumped conceptual models to include semi-distributed (e.g., TOPMODEL, HEC-HMS) and fully distributed (e.g., MIKE SHE, WRF-Hydro) hydrological models, enabling the platform to serve a broader range of watershed scales and operational contexts. / 将模型库从集总式概念模型扩展至半分布式（如TOPMODEL、HEC-HMS）和全分布式（如MIKE SHE、WRF-Hydro）水文模型。
  - *Advanced deep learning coupling*: Integrate more sophisticated physics-ML hybrid paradigms, including differentiable programming that embeds conceptual model equations into trainable neural architectures, and physics-informed neural networks that enforce mass conservation as soft constraints. / 集成更复杂的物理-ML混合范式，包括将概念模型方程嵌入可训练神经架构的可微分编程，以及将质量守恒作为软约束的物理信息神经网络。
  - *Local fine-tuned LLM deployment*: Replace the cloud API with locally hosted open-source LLMs (e.g., Llama, Qwen), fine-tuned on hydrological-domain corpora (calibration reports, flood analysis literature) to improve domain-specific reasoning while eliminating latency, cost, and data privacy concerns. / 用本地部署的开源LLM替代云端API，并在水文领域语料上微调，以提升领域推理能力同时消除延迟、成本和数据隐私问题。
  - *Digital twin integration*: Couple the platform with real-time hydrological sensor networks to enable continuous auto-recalibration as new flood events are observed, forming a self-evolving component within watershed digital twin frameworks. / 将平台与实时水文传感器网络耦合，在新洪水事件观测到时连续自动再率定，构成流域数字孪生框架中的自演化组件。
  - *Bayesian uncertainty quantification*: Integrate full Bayesian inference methods (MCMC, variational inference) to characterize posterior parameter distributions and provide predictive uncertainty bounds alongside deterministic forecasts, enhancing risk-informed decision-making. / 集成完整贝叶斯推断方法以表征参数后验分布并提供预测不确定性界，增强风险知情决策。
